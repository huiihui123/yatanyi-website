## 一、AI 开发省钱实操清单

### 1. 模块化生成，别在一个对话里死磕
- 每做一个功能模块就**新开一个对话**（登录、商品展示、支付、后台分开做）
- 别让 AI 每次都要重读前面 50 轮的历史——对话越长，输入 token 越滚越大，缓存也容易失效
- 一个对话搞定一个功能，干净利落

### 2. 指令要"短准狠"
- 不要写小作文式的提示词，直接说需求：
  - ❌ "请帮我写一个关于家具宣传网站的用户注册页面，要求包括用户名、密码、邮箱输入框，还要有验证码功能……"
  - ✅ "写个用户注册页面，含验证码 + JWT 认证 + 记住密码功能，前端 HTML/CSS/JS 一次性输出"
- 实测提示词从 500 字压到 180 字，**Token 消耗能降 60%**，质量基本不变

### 3. 管住 AI 的输出嘴
- AI 的**输出比输入贵**，所以要在提示词里加一句：
  > "不要寒暄，不要解释，不要复述需求，直接给代码"
- 你还可以给输出设上限（`max_tokens`），比如生成一个页面 2000 token 够了就别让它写到 5000
- 这样每次能省 40%-60% 的输出费用

### 4. 报错了只贴报错信息
- 不要每次贴完整项目代码，直接复制**报错截图里的错误日志**和**相关的那几行代码**就行
- 上下文短了，缓存命中率高，输入费用自然低

### 5. 善用缓存优势
- 你的项目代码、需求说明这些**重复出现的内容**，API 会自动缓存
- 所以同一个项目尽量在相近的时间段集中做，缓存还热乎着，**输入部分几乎白送**

## 二、输入输出成本对比分析

### 典型场景成本对比

| 场景类型 | 输入 | 输出 | 谁烧钱 |
|---------|------|------|-------|
| 写小说 / 故事创作 | 几十 token | 几万 token | **输出** |
| 代码打包（高缓存） | 15M（99%缓存） | 0.1M | 输入（但缓存省了） |
| 多轮客服对话 | 每轮几百 | 每轮几百 | **两头都烧** |
| Agent 多轮推理 | 越往后输入越大 | 每轮不小 | **两头都烧，输入还越来越重** |
| 开发软件/网站 | 简单需求描述 | 完整代码实现 | **输出大头** |

### 省钱核心原则
1. **让输入命中缓存**：重复内容、项目代码在相近时间段集中处理
2. **控制输出量**：指令明确、设上限、不要让它自由发挥太多
3. **避免多轮累积**：分模块、新对话、别在一个会话里死磕

## 三、DeepSeek Harness 规范文档使用指南

### Harness 如何设置规范文档

DeepSeek Harness 没有内置的 `SKILL.md` 机制，但可以通过以下方式实现类似功能：

#### 方法一：项目根目录放规则文件
在项目根目录创建 `.dsh/instructions.md` 文件，写入规范内容：不要寒暄，不要解释，不要复述需求，直接给代码

```markdown
# 项目规范
- 代码注释必须用中文
- 前端用 Vue 3 + Tailwind CSS
- 后端 API 返回格式统一为 { code, data, message }
- 所有文件命名使用小写英文，用连字符分隔
```

Agent 工作时会自动读取并遵循这些规则。

#### 方法二：工作区注入指令
启动 Harness 后，在 **Settings → 工作区** 选中项目目录，在会话输入框附加自定义指令。

#### 方法三：插件系统自定义行为
编写插件，让 Agent 在每次执行任务前先加载指定规范文件。

### 注意事项
- Harness 目前是开发者预览版，会快速迭代
- 最简单的方式：**项目根目录放规则文件 + 发任务时提醒先读规则**

## 四、项目开发规范示例

### 文件命名规范
- ✅ 使用英文命名：`user-login.js`、`product-list.vue`
- ❌ 避免中文命名：`用户登录.js`、`商品列表.vue`
- ❌ 避免空格和括号：`user login.js`、`product(1).vue`

### 代码规范
- 前端：HTML/CSS/JavaScript 或 Vue 3
- 后端：Node.js / Python / PHP
- 数据库：MySQL
- 文件编码：统一 UTF-8

### API 接口规范
- 返回格式：`{ code: number, data: any, message: string }`
- 错误码定义：200 成功，400 参数错误，500 服务器错误

### 开发流程建议
1. 需求分析 → 新对话
2. 功能设计 → 新对话
3. 代码生成 → 新对话
4. 测试调试 → 只贴报错信息
5. 部署上线 → 新对话
