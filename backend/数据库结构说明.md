# 雅檀怡家私城 — 数据库结构说明

> 数据库文件：`backend/yatanyi.db`（SQLite，WAL 模式）
> 当前数据量：7 张业务表 + 1 张系统表；users 7 行 / products 36 行 / orders 14 行 / consultations 9 行 / subscriptions 1 行 / verification_codes 2 行 / cart_items 0 行

---

## 一、总体树形结构图

```
yatanyi.db  ── 雅檀怡家私城数据库（SQLite 单文件）
│
├── 🧍 用户域（账号 + 安全）
│   ├── users ────────────── 用户账户表（含个人资料扩展字段）
│   └── verification_codes ── 短信验证码表（忘记密码/找回密码用）
│
├── 🛋️ 商品域（主数据）
│   └── products ─────────── 商品目录表（36 个商品，4 大分类）
│
├── 🛒 交易域（用户行为闭环）
│   ├── cart_items ───────── 购物车表（挂靠在用户下）
│   └── orders ───────────── 订单表（挂靠在用户下，内含商品快照 JSON）
│
├── 📣 营销 / 服务域（独立表单数据）
│   ├── consultations ────── 客户咨询预约表
│   └── subscriptions ────── 新闻订阅表
│
└── ⚙️ 系统
    └── sqlite_sequence ──── SQLite 自增计数器（所有 AUTOINCREMENT 表共用）
```

---

## 二、表级树形结构（含字段、索引）

### 1. users — 用户账户表

```
users
├── id            INTEGER  PK  自增主键
├── username      TEXT    NOT NULL  UNIQUE  登录名
├── password      TEXT    NOT NULL  密码（SHA-256 哈希）
├── phone         TEXT                手机号
├── email         TEXT                邮箱
├── avatar        TEXT    DEFAULT ''  头像
├── created_at    TEXT    NOT NULL    注册时间
├── last_login    TEXT                最后登录时间
│   ── 以下为个人资料扩展字段（老库迁移时后补）──
├── nickname      TEXT    DEFAULT ''  昵称
├── gender        TEXT    DEFAULT ''  性别
├── age           INTEGER DEFAULT 0   年龄
├── region        TEXT    DEFAULT ''  地区
└── signature     TEXT    DEFAULT ''  个性签名
```

### 2. verification_codes — 验证码表

```
verification_codes
├── id          INTEGER  PK  自增主键
├── phone       TEXT    NOT NULL    接收手机号（对应 users.phone）
├── code        TEXT    NOT NULL    验证码
├── purpose     TEXT    DEFAULT 'reset_password'  用途（重置密码等）
├── expires_at  TEXT    NOT NULL    过期时间
├── used        INTEGER DEFAULT 0   是否已使用（0/1）
└── created_at  TEXT    NOT NULL    创建时间
```

### 3. products — 商品目录表

```
products
├── id              INTEGER  PK  自增主键
├── name            TEXT    NOT NULL          商品名
├── category        TEXT    NOT NULL          分类（sofa=沙发 / bed=床 / table=餐桌 / storage=柜类）
├── price           REAL    NOT NULL          现价
├── original_price  REAL                      原价（划线价）
├── description     TEXT                      商品描述
├── image_url       TEXT                      图片地址
├── rating          REAL    DEFAULT 4.5       评分
├── review_count    INTEGER DEFAULT 0         评价数
├── is_hot          INTEGER DEFAULT 0         是否热销（1/0）
├── is_new          INTEGER DEFAULT 0         是否新品（1/0）
├── created_at      TEXT    NOT NULL          创建时间
└── is_active       INTEGER DEFAULT 1         上架状态（1=上架 0=下架，老库迁移后补）
```

### 4. cart_items — 购物车表

```
cart_items
├── id             INTEGER  PK  自增主键
├── user_id        INTEGER  NOT NULL  所属用户（→ users.id）   [索引 idx_cart_user]
├── product_name   TEXT     NOT NULL  商品名（下单时快照）
├── product_price  REAL     NOT NULL  商品单价（下单时快照）
├── quantity       INTEGER  DEFAULT 1 数量
├── image_url      TEXT               商品图（快照）
└── added_at       TEXT     NOT NULL  加入时间
```

### 5. orders — 订单表

```
orders
├── id            INTEGER  PK  自增主键
├── user_id       INTEGER  NOT NULL  下单用户（→ users.id）   [索引 idx_orders_user]
├── username      TEXT     NOT NULL  用户名（冗余，方便后台直接看）
├── items_json    TEXT     NOT NULL  商品明细快照（JSON 数组，见下）
├── total_amount  REAL     NOT NULL  订单总金额
├── status        TEXT     DEFAULT 'pending'  状态（pending/confirmed）
├── xlsx_path     TEXT                导出的订单 Excel 文件路径
└── created_at    TEXT     NOT NULL  下单时间

items_json 内部结构（一个 JSON 数组，每项为一个商品快照）：
[
  { "product_name": "Test Sofa", "product_price": 3999.0, "quantity": 1, "image_url": "" },
  ...
]
```

### 6. consultations — 客户咨询预约表

```
consultations
├── id            INTEGER  PK  自增主键
├── name          TEXT     NOT NULL  联系人姓名
├── phone         TEXT     NOT NULL  联系电话
├── email         TEXT               邮箱
├── consult_type  TEXT               咨询类型
├── message       TEXT               留言内容
├── status        TEXT     DEFAULT 'pending'  处理状态（pending/contacted/completed）  [索引 idx_consult_status]
├── created_at    TEXT     NOT NULL  提交时间                        [索引 idx_consult_created]
└── ip_address    TEXT               来源 IP
```

### 7. subscriptions — 新闻订阅表

```
subscriptions
├── id          INTEGER  PK  自增主键
├── email       TEXT     NOT NULL  UNIQUE  订阅邮箱
├── created_at  TEXT     NOT NULL  订阅时间      [索引 idx_subs_created]
└── ip_address  TEXT               来源 IP
```

## 三、表间关系图（应用层逻辑外键）

> SQLite 中未声明 FOREIGN KEY 约束，关联关系由后端代码（`app.py`）在应用层维护。

```
                    ┌──────────────────────────────┐
                    │          users               │  ← 唯一的"中心表"
                    │  （用户账户 + 个人资料）        │
                    └──────────────┬───────────────┘
                                   │ 1
              ┌────────────────────┼────────────────────┐
              │ user_id            │ user_id            │ phone（弱关联）
              ▼ N                  ▼ N                  ▼
   ┌───────────────────┐  ┌───────────────────┐  ┌─────────────────────┐
   │    cart_items     │  │      orders       │  │ verification_codes  │
   │     购物车         │  │       订单         │  │      验证码         │
   └───────────────────┘  └───────────────────┘  └─────────────────────┘
   （存商品名/价快照）       （items_json 内嵌商品快照 JSON）
                    │
                    提示：购物车与订单都存"商品名称/价格快照"，
                    与 products 表之间没有外键，商品改价/下架
                    不影响历史订单 —— 这是刻意设计的快照模式。
```

独立表（不依赖任何其他表，纯表单数据）：

```
consultations（咨询预约）   subscriptions（邮件订阅）
        │                          │
        └── 仅存表单内容 + 时间 + IP，与其他表无关联
```

## 四、数据流转逻辑（业务闭环）

```
首页/商品页 ──浏览──▶ products（商品目录，只读展示）
                        │
用户注册/登录 ──▶ users（唯一身份中心，session.user_id）
                        │
加入购物车 ──▶ cart_items（按 user_id 挂靠）
                        │
提交订单 ──▶ orders（结算时把购物车行转成 items_json 快照）
             │         并清空该用户的 cart_items
             ▼
   导出 Excel → backend/订单文件/order_*.xlsx（路径存 xlsx_path）
```

## 五、关键设计要点

1. **中心表是 users**：购物车、订单、验证码都直接或间接挂在用户下，所有接口用 `session.get('user_id')` 取当前用户，后端不信任前端传的 user_id（防 IDOR 越权）。
2. **快照而非外键**：`cart_items` 和 `orders.items_json` 冗余存储商品名称/价格/图片，与 `products` 无硬关联。好处：商品后续改价、下架不影响已生成的订单与购物车显示。
3. **无视图**：数据库没有创建任何 VIEW，所有查询直接走表。
4. **浏览历史不入库**：纯前端 localStorage 实现，减少服务器存储。
5. **索引共 5 个**：`idx_consult_status`、`idx_consult_created`、`idx_subs_created`、`idx_orders_user`、`idx_cart_user`，全部落在高频 WHERE 条件上（订单/购物车按用户查、咨询按状态/时间查）。
